# Интерфейс «О!дин запрос»

Владелец — дизайнер. Streamlit-приложение поверх `ui/client.py`; бэкенда не требует (`AGENT_BACKEND=fake`).

## Запуск
```bash
make ui                      # фейковый агент
make ui-api                  # через FastAPI (в соседнем окне make api)
uv run pytest tests/test_ui.py tests/test_ui_components.py -q
```
Любой экран открывается с демо-данными без агента: `http://localhost:8501/?screen=areas`
(`start`, `working`, `clarify`, `areas`, `results`, `diff`, `cart`, `confirm`, `paid`, `none`).

## Структура
| Файл | Что внутри |
|---|---|
| `ui/app.py` | точка входа: тема, маршрутизация экранов, поле ввода |
| `ui/screens.py` | по функции на экран; запуск агента и переходы (`run_agent`, `go`) |
| `ui/components.py` | HTML-карточки, чистые функции без Streamlit (их тестируем обычным pytest) |
| `ui/theme.py` | цвета, весь CSS, загрузка фото |
| `ui/demo_data.py` | демо-данные в форме `harness/contracts.py` |
| `ui/assets/photos/` | фото для карточек (Freepik, см. раздел «Фото») |
| `.streamlit/config.toml` | тема Streamlit (цвета, шрифт) |

## Экраны и контракт
| № | Экран | Когда показываем | Данные из контракта |
|---|---|---|---|
| 1 | Старт | начало сессии | — (готовые путешествия лежат в `demo_data.TRIPS`) |
| 2 | Агент работает | идёт SSE-поток | события `AgentEvent`: `plan`, `node_start`, `tool_call`, `tool_result`, `verify`, `replan`, `answer` |
| 3 | Уточнение | `mode = clarify` | `AgentAnswer.questions`, `assumptions` |
| 4 | Выбор района | `mode = plan` и есть `destinations` | `DestinationOption`: `best_for`, `why`, `air_temp_c`, `sea_temp_c`, `travel_hours`, `direct`, `est_total_price`, `score` |
| 5 | Результаты | `mode = plan` | `itineraries` (иначе `candidates`): `label`, `total_price`, `tradeoffs`, `checks`, `hotel` |
| 6 | Было → стало | в ответе непустой `changes` | `AgentAnswer.changes`, прошлый ответ хранится в `session_state.prev_answer` |
| 7 | Корзина | только по кнопке «Выбрать этот вариант» (на `confirm_action` показываются варианты, не корзина) | `Itinerary`: `outbound`, `inbound`, `transfers`, `hotel`, `checks` |
| 7а | Подтверждение без вариантов | `mode = confirm_action`, `itineraries` и `candidates` пусты (например, `pending_action.tool = "addon_mock"`) | `text` агента; кнопки «Да» / «Нет» отправляют «да» / «нет» |
| 8 | Оформлено | событие `purchase` | `booking_ref` |
| 9 | Нет решения | `mode = no_solution` | `AgentAnswer.violations` |

Правка параметров на экране «Результаты» уходит агенту как `patch` (`budget_total`, `nights`, `guests_adults`), как в `Agent.stream(..., patch)`.

## Стиль
Плоский светло-серый фон `#F5F5F7`, белые карточки с тонкой рамкой `#E8E8ED`, без цветных пятен.
Синий `#0D41D2` — основной цвет. **Все кнопки только синие**: основная — заливка (hover `#0B38B8`, pressed `#082C94`), вторичная — светло-синяя `#E8EEFD`, текстовая — без фона.
Светло-салатовый `#CDF4B0` — только акцент (метка «Рекомендуем», галочки выполненных шагов, обводка рекомендованного варианта). Красный и жёлтый только для ошибок и предупреждений.
Серые `#F2F2F7` / `#E9E9EE` / `#E5E5EA` / `#D1D1D6`, текст `#14161F` / `#6C6C70` / `#86868B`. Шрифт Inter / системный. Все токены в `ui/theme.py`.

## Состояния компонентов
Лист `docs/ui/screens/10-states.png` показывает каждый компонент в состояниях Default, Hover, Pressed, Focus, Disabled, Loading, Error: кнопки (основная, вторичная, текстовая, иконка), чипы и допущения агента, табы (сегменты и линия), поля ввода, выпадающий список, счётчик, флажок, радиокнопка, переключатель, ползунок, поле запроса, карточки (в том числе выбранная и рекомендованная), уведомления, пустые состояния и шаги.
В коде состояния заданы в `ui/theme.py`: `:hover`, `:active`, `:focus-visible` (кольцо 4 px), `:disabled`, `aria-invalid` для ошибок. Главная кнопка экрана получает контейнер с ключом `main-…` и становится заливкой.

## Как интерфейс говорит с агентом
| Действие | Что уходит агенту |
|---|---|
| Ввод в поле запроса | текст как есть |
| «Выбрать район» или чип «Другие районы» | `patch {"destination": "<name из карточки>"}`, агент пересобирает поездку |
| «Пересчитать» в панели параметров | `patch` только с изменёнными полями (`budget_total`, `nights`, `guests_adults`, `children_ages`); поля берутся из `request`, пустое остаётся пустым, «Взрослых» при `null` показывает 2 (допущение агента); без изменений кнопка неактивна |
| «Подтвердить и оплатить» | текст «да, вариант N» (N с единицы), номер брони приходит событием `purchase` |
| «Применить» на экране «Нет решения» | `patch` из `answer.plan.relax[i]` как есть |

Блок «Что можно поменять» показывается только если в ответе есть `plan.relax` (`[{title, text, result, patch, hotel?}]`). Если там пусто, блока нет.

## Данные на экранах
Все цифры, названия и расписания в карточках приходят от агента (`itineraries`, `destinations`, `candidates`). На главной у карточек
«Готовые путешествия» цен нет: показаны только тип поездки и район, нажатие отправляет агенту готовый запрос.
Числа в `ui/demo_data.py` (цены, расписания, `RELAX`) выдуманы и нужны только для просмотра экранов через `?screen=…`;
в обычной работе они не показываются.

## Что пока не подключено
- Фото в карточках демонстрационные и подбираются по названию места. Для настоящих отелей их надо брать из каталога.
- Streamlit рисует кнопки отдельно от HTML-карточек, поэтому кнопка стоит сразу под карточкой, а не внутри неё.

Картинки экранов и лист состояний в `docs/ui/screens/`. Интерактивный холст с теми же экранами приложен в описании PR.


## Как читаем ответ агента

- Над карточками: только строка «Поездка: …» из `answer.text` и `answer.assumptions[].reason`, каждое с новой строки. Остальной текст агента не показывается.
- Бюджет у агента только на проживание: метка «отель дороже бюджета» и итог в корзине сравнивают его с `itinerary.hotel.price_total`, а не с итогом поездки.
- `checks` с `severity` warning/error (даже при `ok = true`) показываются жёлтым вместе с вариантами решения из `checks[].fixes`; info — зелёным.
- «Другие районы» не включают текущий: выбранный, из `request.destination` или тот, что агент подобрал сам (`itineraries[0].destination_id`).

## Боковое меню

Если рядом с `ui/app.py` есть страницы (`ui/pages/2_metrics.py`), `ui/app.py` подключает их через `st.navigation` и подписывает по-русски: «Приложение» и «Метрики». Новую страницу добавляют в список `extra` в `ui/app.py`. Если страниц нет, меню не показывается.
