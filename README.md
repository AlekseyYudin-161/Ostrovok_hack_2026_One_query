# О!дин запрос — AI-агент для путешествий (трек «О!дин запрос», Ostrovok Tech Hackathon 2026)

Пользователь одним сообщением описывает поездку по Большому Сочи — агент понимает запрос, сам подбирает район,
собирает поездку целиком (отель + дорога туда и обратно + трансферы), проверяет, что всё стыкуется по времени,
и оформляет демо-бронь только после явного «да».

## Быстрый старт

```bash
git clone https://github.com/ostrovok-hackathon-2026/aaateam.git
cd aaateam
cp .env.example .env        # можно пропустить: без .env агент работает офлайн
docker compose up --build
# открыть http://localhost:8080
```

- `http://localhost:8080` — интерфейс (Streamlit).
- `http://localhost:8000/health` — проверка API, ответ `{"status": "ok", ...}`; `POST /chat` — поток событий агента (SSE).

**Режим работы.** Без ключа LLM (`LLM_PROVIDER=fake`, значение по умолчанию в `.env.example`) запрос разбирается
правилами — весь путь работает без сети и без денег. С ключом в `.env` (`LLM_PROVIDER=openai_compat` и переменные
ниже) запрос разбирает модель Qwen3.6-35B-A3B. <!-- TODO: способ передачи ключа жюри — инструкцию оргов (age) добавить, когда опубликуют -->

## Пример

Запрос: `Хочу на море с ребёнком 6 лет в июле на неделю`

Агент:
1. Понимает: море, ребёнок 6 лет, июль, 7 ночей; район не назван.
2. Подбирает район по месяцу и пожеланиям (инструмент `RankAreas`: сезон, погода, дорога) и называет ещё два подходящих.
3. Собирает 3 варианта — «Оптимально», «Дешевле всего», «Комфортно»: отель, рейс/поезд туда и обратно, трансферы,
   итог за поездку и «Минусы» каждого варианта; показывает допущения («Даты не назвали — считаю заезд в пятницу…»).
4. Предупреждает о стыковках с ценой решения («поздний выезд — 1 400 ₽»); ночные прибытия и выезды из отеля
   раньше 06:00 предлагает, только если других вариантов нет.
5. «да» / «да, вариант 2» → демо-бронь `DEMO-…`. Без «да» ничего не оформляется.

Дальше в той же сессии: «а если на 2 дня позже?», «дешевле», «с нами собака», «а в Хосте?» — агент меняет только
названное и показывает «было → стало». Если вариантов нет — честно говорит и предлагает, что поменять, с ценой.

## Запуск для разработки (без Docker)

Требования: [uv](https://docs.astral.sh/uv/) (Python 3.12 он поставит сам).

### Через Makefile
```bash
make setup          # uv sync
make test           # pytest
make lint           # ruff
make api            # FastAPI на :8000 (читает .env)
make ui-api         # Streamlit через API (в соседнем окне — make api)
make eval-offline   # eval на всех кейсах без сети и без денег
make eval           # eval с моделью из .env → evals/reports/
```

### Вручную
```bash
uv sync
uv run pytest -q
uv run uvicorn app.main:app --reload --port 8000 --env-file .env   # без .env — убрать флаг
AGENT_BACKEND=http API_URL=http://localhost:8000 uv run streamlit run ui/app.py
uv run python -m evals.runner
```

## Зависимости и переменные окружения

Рекомендованные ресурсы: 1–2 CPU, 1 ГБ RAM, Docker с Compose v2. Замер (`docker stats`, MacBook Air M1):
API ≈190 МБ, интерфейс ≈130 МБ памяти; первая сборка `docker compose up --build` — около 2,5 мин.
Внешних сервисов (БД, кэш) нет: каталог — файлы в `synth/data/`, состояние диалога — в памяти процесса.

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `LLM_PROVIDER` | `fake` | `fake` — разбор правилами, без сети; `openai_compat` — модель по OpenAI-совместимому API |
| `LLM_BASE_URL` | — | например `https://api.kodikrouter.ru/v1` (запасной — routerai, локально — Ollama/vLLM) |
| `LLM_API_KEY` | — | ключ с лимитом бюджета; в git не коммитить |
| `LLM_MODEL` | — | `qwen/qwen3.6-35b-a3b` |
| `LLM_EXTRA_BODY` | — | `'{"reasoning": {"enabled": false}}'` — обязательно для Qwen3.6, в одинарных кавычках |
| `AGENT_BACKEND` | `graph` | API: `graph` — агент LangGraph, `fake` — заглушка; UI: `http` — через API |
| `API_URL` | `http://localhost:8000` | адрес API для интерфейса (в Docker — `http://api:8000`) |
| `LOG_LEVEL` | `INFO` | уровень логов (пишутся в stdout) |
| `LANGFUSE_TRACING_ENABLED`, `LANGFUSE_PUBLIC_KEY`, `LANGFUSE_SECRET_KEY`, `LANGFUSE_BASE_URL` | `false` | трассировка в Langfuse (опционально) |

## Данные

Сидирование не нужно: демо-каталог лежит в репозитории (`synth/data/*.json`, `reviews.jsonl`) и читается при старте.
Офферы на даты считаются детерминированно (`synth/pricing.py`): тот же запрос — та же цена.
Пересобрать каталог (нужен ключ генератора текстов): см. `synth/README.md`.

## Как устроено

```
Streamlit (ui/) ──HTTP/SSE──► FastAPI /chat (app/) ──► GraphAgent (LangGraph, harness/agent_graph.py)
                                                          │
  guard (защита от инъекций) → understand (LLM → JSON по схеме, проверка правилами)
     → inspire (район по месяцу: RankAreas)  |  clarify  |  out_of_scope (не Сочи → похожий район)
     → search: сборка поездки (harness/trip.py на каталоге synth/) + проверка стыковок (harness/checks.py)
     → offer (3 варианта, «Минусы», допущения) → confirm (пауза, ждём «да») → purchase (демо)
     └→ no_solution → предложения, что поменять («да» применяет первое)
```

- **LLM только разбирает запрос** в JSON по строгой схеме; цены, даты, стыковки и тексты ответа считает код —
  поэтому цены в ответе всегда из данных, а системный промпт не попадает в ответ.
- **Состояние сессии** — чекпоинтер LangGraph (`thread_id = session_id`): пауза перед покупкой и пересборка.
- **Контракт** между модулями — `harness/contracts.py` (Pydantic), версия 1.2.

## Безопасность

- Защита от prompt injection на русском и английском: «игнорируй инструкции», «покажи промпт», «ты теперь…»,
  «оформи без подтверждения», подделка ролей, невидимые и полноширинные символы (`harness/security.py`).
- Отзывы и любые внешние тексты — недоверенные данные: команды агенту из них вычищаются.
- Покупка — только через паузу и явное «да»; номер варианта и цена сверяются с показанными.
- Ключи — только в `.env` (в `.gitignore`), в репозитории их нет.

## Ценность для бизнеса

- **Один запрос вместо десятка поисков**: отель, дорога и трансферы собраны и проверены вместе — меньше брошенных сессий.
- **Меньше испорченных поездок**: стыковки (ночной прилёт, лишняя ночь, ранний выезд) проверяются кодом до оплаты,
  а не после — меньше обращений в поддержку и отмен.
- **Доверие**: агент показывает допущения и «минусы» вариантов, цены — только из данных, бронь — только после «да».
- **Готов к интеграции**: данные подключены в одной точке (`harness/trip.py` и инструменты `synth/tools.py`) —
  демо-каталог заменяется на API поставщика без переделки графа агента.

## Ограничения

- Данные синтетические; одна локация — Большой Сочи (запрос в другое место → честный ответ и похожий район в Сочи).
- Оплата — имитация.
- Состояние диалога хранится в памяти процесса: после перезапуска API сессии начинаются заново.

## Команда

Тимлид (агент, API, интеграция), ML-инженер (каталог и инструменты `synth/`, развёртывание), DA (eval и метрики `evals/`),
дизайнер (интерфейс `ui/`). Документы: DesignDoc и ADR — в Buildin команды.

## Правила разработки

- Ветки `feature/<задача>` от `dev`; в `dev` — только через PR, ревьюит и мержит тимлид.
- Перед PR: `make test && make lint`.
- `main` — версия для сдачи: тимлид вливает `dev → main`, на последнем коммите — тег `submission`.
- Ключи и `.env` не коммитим.
