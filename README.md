# О!дин запрос — AI-агент для путешествий (трек «О!дин запрос», Ostrovok Tech Hackathon 2026)

Пользователь одним сообщением описывает поездку по Большому Сочи — агент понимает запрос, сам подбирает район,
собирает поездку целиком (отель + дорога туда и обратно + трансферы), проверяет, что всё стыкуется по времени,
объясняет выбор и оформляет демо-бронь только после явного «да». После брони — ранний заезд, поздний выезд,
смена брони.

- Видео-демонстрация: **https://drive.google.com/drive/folders/1_Yrd1DaERqY0W-X2OfCpZlaCkSFZFYVt**
- Развёрнутый сервис: **http://195.209.209.206:8080**

> Все данные — демо: синтетический каталог `synth/` (отели, тарифы, расписания, трансферы и отзывы вымышленные;
> районы Большого Сочи и климатические нормы — условно реальные). Оплата — имитация, реальных броней нет.

## Быстрый старт

```bash
git clone https://github.com/ostrovok-hackathon-2026/aaateam.git
cd aaateam
cp .env.example .env        # можно пропустить: без .env агент работает офлайн (запрос разбирают правила)
docker compose up --build
# открыть http://localhost:8080
```

- `http://localhost:8080` — интерфейс (Streamlit).
- `http://localhost:8000/health` — проверка API, ответ `{"status": "ok", ...}`; `POST /chat` — поток событий агента (SSE).

### Запуск с моделью (ключ для жюри)

Ключ LLM передан организаторам в зашифрованном виде: `secrets.env.age` в корне репозитория (age, публичный ключ
организаторов). Провайдер — **kodikrouter** (OpenAI-совместимый API), модель — **`qwen/qwen3.6-35b-a3b`**
(Qwen3.6-35B-A3B). Ключ отдельный, только для жюри, с лимитом расходов.

```bash
age -d -i <закрытый_ключ_организаторов> -o .env secrets.env.age
docker compose up --build
# открыть http://localhost:8080
```

Без `.env` агент тоже запускается, но разбирает запросы правилами (офлайн-режим, без модели и без сети).

## Пример

Запрос: `Хочу на море с ребёнком 6 лет в июле на неделю`

Агент:
1. Понимает: море, ребёнок 6 лет, июль, 7 ночей; район не назван.
2. Подбирает район по месяцу и пожеланиям (инструмент `RankAreas`: сезон, погода, время в дороге, цена)
   и называет ещё два подходящих.
3. Собирает 3 варианта — «Оптимально», «Дешевле всего», «Комфортно»: отель, рейс/поезд туда и обратно, трансферы
   (с ребёнком — такси, а не долгий автобус), итог за поездку. У каждого — «Почему» (скоринг отелей) и «Минусы».
4. Показывает допущения: «Даты не назвали — считаю заезд в пятницу…», «Считаю на 2 взрослых — поправьте».
5. Предупреждает о стыковках с ценой решения («после выезда до рейса ≈7 ч — поздний выезд 1 400 ₽»);
   ночные прибытия и выезды раньше 06:00 предлагает, только если других вариантов нет.
6. «да» / «да, вариант 2» / «давай Вертикаль» / «нет, вариант 3» → демо-бронь `DEMO-…`. Без «да» ничего не оформляется;
   непонятный выбор — переспрашивает.
7. После брони: «можно ранний заезд?» → цена отеля → «да» → добавлено к брони. Новое оформление заменяет бронь.

Дальше в той же сессии любое допущение правится обычной фразой: «давай в Хосте», «с 14 ноября», «нас трое»,
«едем из Казани», «а если на 2 дня позже?», «дешевле», «с нами собака», «дети 5 и 8 лет» — агент меняет только
названное и показывает «было → стало» («Изменил: Откуда: Москва → Казань»). Если вариантов нет — честно говорит и предлагает,
что поменять, с ценой из каталога («да» применяет первое).

## Запуск для разработки (без Docker)

Требования: [uv](https://docs.astral.sh/uv/) (Python 3.12 он поставит сам).

### Через Makefile
```bash
make setup          # uv sync
make test           # pytest
make lint           # ruff
make api            # FastAPI на :8000 (читает .env)
make ui-api         # Streamlit через API (в соседнем окне — make api)
make eval-offline   # eval на всех кейсах без сети и без денег
make eval           # eval с моделью из .env → evals/reports/
```

### Вручную
```bash
uv sync
uv run pytest -q
uv run uvicorn app.main:app --reload --port 8000 --env-file .env   # без .env — убрать флаг
AGENT_BACKEND=http API_URL=http://localhost:8000 uv run streamlit run ui/app.py
uv run python -m evals.runner
```

## Зависимости и переменные окружения

Рекомендованные ресурсы: 1–2 CPU, 1 ГБ RAM, без GPU (модель вызывается по API), Docker с Compose v2.
Замер (`docker stats`, MacBook Air M1): API ≈200 МБ, интерфейс ≈170 МБ памяти; первая сборка
`docker compose up --build` — около 2 мин. Внешних сервисов (БД, кэш) нет: каталог — файлы в `synth/data/`,
состояние диалога — в памяти процесса.

|---|---|---|
| `LLM_PROVIDER` | `fake` | `fake` — разбор правилами, без сети; `openai_compat` — модель по OpenAI-совместимому API |
| `LLM_BASE_URL` | — | `https://api.kodikrouter.ru/v1` (запасной — routerai, локально — Ollama/vLLM) |

## Данные

Сидирование не нужно: демо-каталог лежит в репозитории (`synth/data/*.json`, `reviews.jsonl`) и читается при старте.
Офферы на даты считаются детерминированно (`synth/pricing.py`): тот же запрос — та же цена.
Пересобрать каталог (нужен ключ генератора текстов): см. `synth/README.md`.

## Как устроено

```
Streamlit (ui/) ──HTTP/SSE──► FastAPI /chat (app/) ──► GraphAgent (LangGraph, harness/agent_graph.py)
                                                          │
  guard (защита от инъекций) → understand (LLM → JSON по схеме, проверка правилами)
     → inspire (район по месяцу: RankAreas)  |  clarify  |  out_of_scope (не Сочи → похожий район)
     → search: сборка поездки (harness/trip.py на каталоге synth/, скоринг отелей synth/scoring.py)
               + проверка стыковок (harness/checks.py)
     → offer (3 варианта, «Почему», «Минусы», допущения) → confirm (пауза, ждём «да») → purchase (демо)
     └→ no_solution → предложения, что поменять, с ценой («да» применяет первое)
  после брони: addon (ранний заезд / поздний выезд) → confirm → purchase
```

- **LLM только разбирает запрос** в JSON по строгой схеме; цены, даты, стыковки и тексты ответа считает код —
  поэтому цены в ответе всегда из данных, а системный промпт не попадает в ответ.
- **Состояние сессии** — чекпоинтер LangGraph (`thread_id = session_id`): пауза перед покупкой и пересборка.
- **Контракт** между модулями — `harness/contracts.py` (Pydantic), версия 1.2.
- **Наблюдаемость** — Langfuse: один трейс на ход диалога (узлы графа, вызов модели, токены), все ходы — в одной
  сессии; стоимость запроса в ₽ — в каждом ответе API (`usage`) и в отчёте eval.

## Безопасность

- Защита от prompt injection на русском и английском: «игнорируй инструкции», «покажи промпт», «ты теперь…»,
  «оформи без подтверждения», подделка ролей, невидимые и полноширинные символы (`harness/security.py`).
  Если в запросе есть и поездка, и атака — поездку собираем, атаку игнорируем и говорим об этом.
- Отзывы и любые внешние тексты — недоверенные данные: команды агенту из них вычищаются.
- Покупка — только через паузу и явное «да»; номер варианта и цена сверяются с показанными.
- Ключи — только в `.env` (в `.gitignore`); жюри — в зашифрованном `secrets.env.age`.

## Ценность для бизнеса

- **Один запрос вместо десятка поисков**: отель, дорога и трансферы собраны и проверены вместе — меньше брошенных
  поисков и выше доля покупок поездки целиком.
- **Меньше испорченных поездок**: стыковки (ночной прилёт, лишняя ночь, ранний выезд) проверяются кодом до оплаты,
  а не после — меньше обращений в поддержку и отмен.
- **Доверие**: агент показывает допущения, «Почему» и «Минусы» вариантов, цены — только из данных,
  бронь — только после «да».
- **Допродажи после покупки**: ранний заезд, поздний выезд — по цене отеля, одной фразой.
- **Дёшево в эксплуатации**: модель только разбирает запрос — 0,026 ₽ на запрос.
- **Готов к интеграции**: данные подключены в одной точке (`harness/trip.py` и инструменты `synth/tools.py`) —
  демо-каталог заменяется на API поставщика без переделки графа агента.

## Ограничения

- Данные синтетические; одна локация — Большой Сочи (запрос в другое место → честный ответ и похожий район в Сочи).
- Оплата — имитация.
- Пожелания, которых нет в данных (например, «отель с аквапарком»), не фильтруются.
- У трёх вариантов поездки разные отели; если подходящих отелей мало (например, с животным), вариантов может быть два.
- Состояние диалога хранится в памяти процесса: после перезапуска API сессии начинаются заново.

## Структура репозитория

```
app/                  # FastAPI: /chat (поток событий агента, SSE), /health
harness/              # агент LangGraph: граф (agent_graph.py), контракт (contracts.py), сборка поездки (trip.py),
                      #   проверка стыковок (checks.py), даты, районы, защита от инъекций (security.py), LLM-клиент
synth/                # демо-каталог: данные (data/), цены и офферы (pricing.py), инструменты агента (tools.py), скоринг отелей
evals/                # eval: тестовые кейсы (golden/), прогон (runner.py), симулятор пользователя, метрики, отчёт (reports/)
ui/                   # интерфейс Streamlit: экраны, компоненты, тема, страница метрик (pages/)
tests/                # pytest
scripts/              # служебные: проверка .env, проба провайдера модели, eval разбора запроса
make/, Makefile       # make setup / test / lint / api / ui-api / eval / eval-offline
fixtures/             # тестовые данные отелей для режима без каталога
docs/ui/              # описание интерфейса и скриншоты экранов
Dockerfile, docker-compose.yml   # api :8000 + интерфейс :8080
.env.example          # переменные окружения (копировать в .env)
secrets.env.age       # ключ модели для жюри (зашифрован age)
```
